# i18n — translating `.as` texts

Atscript ships no translation runtime. Texts in `.as` files are **message ids** (source language, as written); validator built-in messages use the error **code** as id. Docs: https://atscript.dev/packages/typescript/i18n

## Quick start (server)

```ts
import { serializeAnnotatedType, translateServed, VALIDATOR_MESSAGES } from '@atscript/typescript/utils'

const json = serializeAnnotatedType(Signup) // once
const { value, texts } = translateServed(json, text => dict[text]) // per locale; undefined = keep
const templates: Record<string, string> = {}
for (const code of Object.keys(VALIDATOR_MESSAGES)) if (dict[code]) templates[code] = dict[code] // '{min}' placeholders kept
send({ ...value, $i18n: { ...templates, ...texts } }) // templates first, texts win
```

## Quick start (client)

```ts
const type = deserializeAnnotatedType(served) // ignores $i18n
const v = type.validator()
if (!v.validate(data, true)) localizeErrors(v.errors, messagesTranslator(served.$i18n ?? {}))
```

## Rules

| #   | Rule |
| --- | ---- |
| 1   | Id = the annotation text as written (`@meta.label 'Email'` → `'Email'`); built-in validator message → `code` (`MIN_LENGTH`), template with `{name}` placeholders. Errors keep `code` / `params` — branch on those, never on `message`. |
| 2   | Which keys hold text = their spec's `userText` flag, read at runtime with `userTextOf(key)` → `true` / `'expression'` / `string[]` (`'name()'` = expression field) / `undefined`. Details: [annotations.md](annotations.md) (`userText`). |
| 3   | `t` returning `undefined` (any non-string) keeps the text. `translateServed(json, t)` walks ANY JSON: every object under a `metadata` key, any depth (props, items, `$ref` uses, ref targets, annotation-value targets). A primitive's built-in format message (`string.email` pattern → `EMAIL`, …) is NOT translated: the client reports it by code via `$i18n`. Never mutates input; returns the input itself when nothing translated → cache per (type, locale). |
| 4   | Expression values stay as written. Their string literals (`'…'`, `"…"`, `` `…` `` without `${}`; literals inside `${}` count; comments/regex skipped) go through `t`; translated ones land in `texts` (literal → translation). Client matches a computed result exactly — `'Hello ' + name` is not translatable; return whole sentences. |
| 5   | `$i18n` = one flat map: translated validator templates by code, then `texts` over them (`{ ...templates, ...texts }`). Optional field of `TSerializedAnnotatedType`. Feed it to `messagesTranslator()`. |
| 6   | Flag a plugin arg `userText: 'expression'` only when it is evaluated as code; plain text args stay `userText: true`. |
| 7   | Labels not written in an annotation (derived from field names) have no id — not translated. |
| 8   | `@atscript/moost-validator` error bodies (`errors`) are translated per request by a `moost` translator (`setTranslator()`): [moost-validator.md](moost-validator.md#error-shape). |
| 9   | Types compiled into the client (not served), since 0.2.10: `translateUserText(key, value, t)` translates ONE metadata key's live value by the same rules as `translateServed` (same keys, `{ message }` objects, `multiple` lists, option labels, format messages kept, `undefined` keeps). One catalogue for both sides. Same reference when unchanged, never mutates. Expression keys come back as written (translate their results with `t`). |

## Client-side texts of a compiled type

```ts
import { translateUserText } from '@atscript/typescript/utils'

const t = (text: string) => dict[text] // undefined = keep
const prop = Signup.type.props.get('email')!
translateUserText('meta.label', prop.metadata.get('meta.label'), t) // 'Email' -> dict['Email']
translateUserText('meta.required', prop.metadata.get('meta.required'), t) // { message } translated
```
